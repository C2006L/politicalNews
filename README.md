# 时政聚合平台 (Political News)

面向两类用户：
- 考公/考编备考用户（需要稳定、可回看、可检索的时政资料）
- 日常关注时政用户（需要权威来源、更新及时、阅读简洁）

本项目已部署在线版本，普通用户无需自行部署，直接访问即可：

## 功能概览

- 每日阅读首页：综合、考研政治、公考常识、申论面试四种方向，支持主题筛选和分页
- 阅读整理：同日同标题稿件合并展示，推荐依据可展开；仅按规则排序，不代表命题预测或完整事件聚合
- 阅读工具：已读标记、浏览器本地收藏、原文链接和往期回顾；收藏不跨设备同步
- 内容区分：原文导读与规则阅读提示分别展示，当前未接入 AI 总结

- 权威来源聚合：政府网、人民网、新华网、中国新闻网、央视网、外交部等
- 页面导航：今日时政、昨日时政、分类专题、数据源、按月归档、同步状态
- 检索能力：关键词搜索、年份筛选（最低到 2025）、按月归档展开
- 数据策略：每小时自动同步（北京时间），支持手动同步和回填
- 内容策略：保留原文链接，不做 AI 改写
- 终端适配：桌面 + 移动端自适应

## 本地配置与离线测试

使用 Python 3.13 安装 `requirements.txt` 与 `requirements-dev.txt`。应用会在数据库初始化前自动加载项目根目录 `.env`，已存在的系统环境变量优先。修改 `.env` 后需重启进程。

设置以下三项可关闭自动采集（不禁止手动管理接口）：

```dotenv
AUTO_SYNC_ON_STARTUP=0
BOOTSTRAP_RECENT_NEWS_ON_STARTUP=0
SCHEDULER_ENABLED=0
```

`SCHEDULED_SYNC_INTERVAL_HOURS` 是从调度器启动后计算的实际小时间隔，不保证整点执行。测试会在导入应用前使用临时数据库，并禁止外部网络及真实采集线程，不依赖工作目录里的新闻库：

```bash
python -m pytest
python -m mypy app/ --ignore-missing-imports
python -m flake8 app/ --count --select=E9,F63,F7,F82 --show-source --statistics
```

非 UI 实施记录及剩余任务见 [功能待办规划](docs/NON_UI_ROADMAP.md)。


## 公众号研读（首版）

`/learning` 提供公众号考点摘录与折叠问答，`/api/learning` 和 `/api/learning/{id}` 提供结构化结果。每条内容保留原文段落编号、账号及链接；规则摘录不等于 AI 总结，不宣称已核对教材或完整覆盖音视频和图片。

本地 WeRSS 目前订阅肖秀荣教授和考研政治徐涛。配置 `WERSS_DATABASE_PATH` 指向其 SQLite 数据库后，主项目只读导入白名单账号的文字正文，保存至独立 `learning_materials` 表。启动通过 `init_db()` 执行版本化 SQLite 迁移；旧库升级前应备份。该桥接仅适用于两个服务能访问同一磁盘文件的部署，尚非通用远程 RSS 接口。

本机启动：

```powershell
.\scripts\run_learning_local.ps1
```

入口为 `http://127.0.0.1:8004/learning`。脚本先导入一次，然后随主服务每 15 分钟导入已采集内容；WeRSS 自身每两小时获取文章。关闭主项目调度器后不会自动导入。新增内容按来源 ID 去重，正文或标题变化时重新整理，资料修订以递增版本保存，历史正文、标题和依据可回看。

手动导入接口为 `POST /api/learning/sync`，通过 `X-Sync-Token` 请求头提交已配置的 `SYNC_ADMIN_TOKEN` 或本机管理口令；未配置任何管理口令时禁止该接口写入。也可在本地执行 `from app.materials import sync_materials; sync_materials()`。

限制：目前按已知模板识别考点和编号自测，不支持的文章保留文字并提示待整理；作者标星与系统判断分开。两个账号主题不同时分别呈现，不强行合并成一个结论。来源可能漏采多篇更新，发布时间未验证；尚未接入模型摘要、音频转写或跨文章语义合并。关系审核可在下述网页完成，不能代替教材内容校验。


公众号运行诊断见 `/status` 和 `/api/learning/status`：上游库可读不代表授权正常，导入无新增不代表公众号无更新。主项目导入状态持久化；失败保留最后成功时间，重启识别未完成导入。文章来源时间未确认时保持空值，导入时间单独记录。

## 数据库升级与学习资料版本

当前数据库版本为 6。启动时按 `schema_migrations` 顺序升级；新库和原有无版本号数据库均适用。升级不改变新闻与学习资料 ID，较新且不受当前程序支持的数据库版本会拒绝启动。现阶段仅支持 SQLite。

旧学习资料升级时保存为版本 1，标记 `legacy_snapshot`：可保留升级前已有的标题、结构化正文和依据，但无法恢复此前没有保存的原始 HTML。后续更正与正文快照在同一事务提交，导入失败不会留下半条修订；重复导入不增加版本。历史版本为只读。

版本接口：`GET /api/learning/{id}/revisions`、`GET /api/learning/{id}/revisions/{revision}`。固定引用可使用 `/learning/{id}?revision=1#e-L1`，普通 `/learning/{id}` 和已有收藏仍打开最新内容。

升级前执行（目标文件必须尚不存在）：

```powershell
python scripts/database_backup.py test.db backup-before-upgrade.db
```

恢复时先停止应用及后台写入，再将备份复制到一个新文件并把 `DATABASE_URL` 指向它。脚本使用 SQLite backup API 并检查完整性，禁止覆盖已有目标；不会自动执行破坏性的降级迁移。若需要回到升级前版本，应同时恢复对应应用版本与升级前备份。

## 考点关联（候选关系）

从 `/learning` 的“按考点研读”进入 `/knowledge`，或从资料详情进入对应考点。当前目录覆盖 17 种明确的题目或表述模板，考点使用稳定编号；只关联已抽取、具有有效原文段落依据的条目，不以关键词相同直接合并。新资料和更正导入时自动关联，启动时补齐已有版本的关系，重复运行不重复添加。

历史样本整理使用 `rules-3`：合并句内格式标签，保留段落边界，识别“重温重要提法”“点拨”“命题分析”；排除明确的经典干扰项及考查频率说明。题目和原文提法分别保存，页码括注只用于匹配时去除，不改变原文证据。新增的五类明确问句/提法对应关系采用 `catalog-v2`；全部为候选，不自动确认或合成统一答案。规则升级生成新资料修订，旧原文快照与固定引用继续保留，旧复习卡不会自动转移进度。

本机当前 55 篇样本中，41 篇有文字条目；17 个考点中 5 个有双账号材料，考点首页提供对照入口。图片式交互题尚未 OCR，不能从文字问答数量推断整篇课程覆盖。详见 [历史样本报告](docs/HISTORY_SAMPLE_REPORT.md)。

`GET /api/knowledge` 返回索引；`GET /api/knowledge/{point_id}` 返回各来源的问答、作者标记、待核对提示与固定版本依据。默认只展示每篇资料最新版本的关联，`?history=true` 可查看历史关联；不同老师的答案分别呈现。教材版本尚未指定，不代表已对照某年考试大纲。

关系初始为 `candidate`。管理员可调用 `PUT /api/knowledge-links/{link_id}/review`，通过 `X-Sync-Token` 请求头提交已配置的 `SYNC_ADMIN_TOKEN`，JSON 请求体为 `{"status":"confirmed"}`、`{"status":"rejected"}` 或 `{"status":"candidate"}`。拒绝的关联不再展示，重建保留审核决定；确认只针对当前固定版本，后续更正的关系仍需重新确认。网页操作见下述关联审核说明。

这是基于明确模板的候选组织能力，未接入模型或向量检索，不自动生成跨来源统一答案，也尚未把图像或音频内容关联到考点。现有两篇真实资料分别命中不同考点，多来源同考点展示通过合成用例验证，不能据此宣称真实资料已形成交叉印证。新闻关联见下节。

## 新闻与考点关联

新闻保存或更正时，在同一事务匹配已知考点；启动时扫描已有新闻补齐关系。当前为 `news-sentence-v1` 规则：明确概念组合必须出现在同一标题或正文句子内，不跨句拼接、不使用摘要兜底，不把泛泛提及“创新”等词直接当成考点。新质生产力与科技创新还需出现核心、驱动、支撑等关联表述，排除仅同句参访介绍的情况。超长且无法分句的片段跳过。

每日阅读显示关联考点入口，新闻详情显示匹配理由和原文句子；考点详情将公众号理论、自测及相关新闻放在同一页。新闻列表每页 20 条，按刊载记录计数，转载可能重复，不代表独立事件或独立证据数量。未命中的新闻保留原样，不强行归类。

- `GET /api/knowledge/{point_id}?page=1` 的 `news` 字段提供当前新闻关联，`?history=true` 包含历史快照。
- `GET /api/news/{news_id}/knowledge` 提供新闻到考点的反向关系。
- `GET /api/knowledge-news-links/{link_id}` 和 `/knowledge/news-links/{link_id}` 提供匹配时的新闻快照、命中字段、句子偏移、原文句子及规则版本。
- `PUT /api/knowledge-news-links/{link_id}/review` 支持 `candidate`、`confirmed`、`rejected`，请求体及 `X-Sync-Token` 鉴权与资料关联审核一致。重建不覆盖审核决定，拒绝的关系不再展示。

每条关系保存当时的标题、正文、摘要、来源、URL、发布时间及内容指纹，原有新闻表结构不变。最新新闻与快照指纹不一致时，旧关系不再算作当前关系；更正后匹配生成新的候选，旧确认不自动沿用。这里保存的是“匹配时的快照”，不是新闻库所有文章的完整修订历史，也不保存尚未命中的旧正文。历史关联页面提供保存时的原站链接及当前新闻入口。

关联仅表示供联系理论阅读，未对照指定年度教材，没有模型语义推理、考试预测或跨新闻统一结论；人工审核支持网页及管理 API。

## 网页关联审核

从考点索引的“维护关联与审核记录”进入 `/review`。可按公众号/新闻及待确认/已确认/已排除筛选，每页 20 条，展开匹配时的全文，填写备注后确认、排除或恢复待确认。网页队列只列当前版本，历史关系继续保留。确认的是与考点的关联，不代表已对照教材确认整篇答案。

若已配置 `SYNC_ADMIN_TOKEN`，直接输入该令牌。未配置时，可在运行程序的本机浏览器首次设置至少 10 个字符的管理口令；数据库仅保存随机盐及 PBKDF2-SHA256 校验值，页面不把口令写入 localStorage 或 sessionStorage。首次设置限 loopback 客户端、localhost/127.0.0.1/::1 主机、同源请求及自定义请求头，配置后不可再次初始化。管理口令用于关系审核和已采集公众号资料导入，其他新闻采集接口沿用原配置。忘记本机口令时可由维护者配置 `SYNC_ADMIN_TOKEN` 并重启，配置令牌优先于本机口令。

受保护的 `GET /api/review/queue` 与 `/api/review/events` 分页提供队列和操作记录。原关系审核 PUT 接口保留兼容，新增可选 `note`（最多 500 字）和 `expected_status`。网页提交时携带原状态；状态已变更返回 409。状态变更与日志在同一事务提交，日志失败时回滚关系，不重复记录无变化操作。

日志保存来源类型、关联编号、考点、变更前后状态、备注及 UTC 时间。只记录功能启用后的操作，不补造既有审核历史；目前使用共享管理口令，不区分具体操作人，没有多角色账号体系。需要恢复已排除关系时在审核页切换“已排除”，查看全文再恢复；普通阅读页仍隐藏已排除关系。

## 公众号导入恢复与扫描覆盖

从公众号列表或状态页进入 `/learning-import`，查看文章库可读性、两个账号已存/有文字/待正文数量、本批结果、上次扫描尚余数量与最近一轮扫描记录。输入管理口令可继续下一批或重试失败任务；此操作只整理 WeRSS 已保存的正文，不触发扫码或代替上游采集。

每批最多 200 篇，按稳定来源文章 ID 分页，游标与资料、修订和关联同一事务提交。下一次手动或定时导入从保存位置继续；一轮结束后从头重新检查，补齐的旧正文和更正会在后续轮次处理，未通过检查的正文不会阻塞后续文章。新来源路径自动重置扫描，异常游标保守重扫并依靠来源 ID/指纹去重，不删除已有资料。

`/api/learning/status` 新增 `scan` 信息，`result.scanned`、`result.remaining` 为本批检查数和快照中的剩余量。扫描完成仅指本地上游库已有正文，不证明公众号列表完整、账号授权有效或没有漏采；当前最新一篇通道的限制不变。运行中断、源文件缺失、库暂时占用和结构不兼容分别提示；结束状态持久化失败而任务锁已释放时，页面可重试，不会一直禁用操作。当前仅支持单进程，不是跨进程协调锁。

本机启动脚本在资料源暂不可用时仍启动已有资料阅读服务；主数据库初始化/迁移失败仍阻止启动。扫描进度使用既有 AppState 存储，不改变数据库版本。首次部署大库需要多批导入；大量文章的复查时效取决于库规模和每 15 分钟的调度周期，不能承诺全部变化立即更新。

### 主动检查上游通道

`/learning-import` 新增“主动检查上游通道”。它只通过 WeRSS 的 `/weread/mp/test` 检查两个白名单公众号的最新文章入口，不请求扫码状态接口、不读取微信 Cookie、不抓正文、不把测试成功当成采集完成或完整登录验证。结果进入 `/api/learning/status` 的 `upstream_check`，与文章库可读性、导入结果分开。

可区分 WeRSS 管理接口凭据失效、接口不可达、响应不兼容、目标入口明确拒绝登录和网络失败。`-2041`、风控或限额等只标为受限/不兼容，不直接断言 Cookie 过期。成功结果为 `not_rejected_at_check`，其含义仅是指定入口当时未拒绝访问；正文与历史覆盖仍未验证。

配置 `WERSS_API_URL`（只允许本机 HTTP 服务根地址）和 `WERSS_API_TOKEN_FILE`（仓库外私有凭据文件）后启用。支持普通 Bearer 文件或 JSON `{key,secret}` 的 WeRSS Access Key；不把这些内容写进主项目数据库、页面、日志或 Git。关闭自动任务时只手动检查，开启时每两小时检查一次，启动时若记录已过时则后台检查；主动按钮至少间隔一分钟，结果超过两小时标为过时。失败保留最近两个入口均可访问的时间，重启中断可重试。

本机部署已创建有效期 90 天的独立接口访问凭据，保存在 WeRSS 私有数据目录，启动脚本自动使用；短期管理员登录令牌不适合定时任务。维护者也可使用 `scripts/setup_werss_access.py --admin-token-file 私有管理员令牌文件 --output 仓库外私有文件` 创建，脚本申请 `article:read` 标记，固定调用仅用于检查，不对上游其他接口的权限隔离作保证。脚本不覆盖已有文件；写文件失败会尝试撤销本次新建的 key。到期后在 WeRSS 重新创建或更新凭据，保存到新的私有文件并切换环境配置，旧凭据可在 WeRSS 撤销。

当前仍未解决最新一篇通道对多篇更新/历史文章的覆盖限制；未采到的未知文章无法靠这个检查补回。已知文章的缺失正文可使用下述恢复队列，不能据入口可访问推断正文已完整取得。

### 恢复已知缺正文

在 `/learning-import` 的“恢复已知缺正文”使用同一管理口令加入任务。只选择两个白名单账号中上游已经保存、正文标记缺失或 HTML 为空且网址有效的记录；已有正文不会强制重抓。每次队列最多 3 篇，串行提交，相邻提交至少 30 秒。数据库版本 6 保存任务状态；普通刷新页面只读取状态，不提交采集。

WeRSS 接收或报告任务成功都不算恢复完成。只有上游库实际出现通过校验的正文，并成功导入主项目，才显示完成；定向导入复用资料修订和考点关联流程，不移动普通批量扫描游标。验证页、正文不足、凭据失效、任务丢失分别提示，原有资料保留。提交响应丢失或上游任务重启丢失时标为未确认，不盲目重发；等待十分钟后可明确重试。进程重启保留队列，正在提交但结果未落盘的任务按未确认处理。

需要额外配置 `WERSS_RECOVERY_TOKEN_FILE`，使用仓库外私有文件；维护者可用上述设置脚本加 `--recovery` 创建独立恢复凭据，申请 `article:read` 和 `article:sync` 标记。启动脚本检测本机既有私有文件后启用；不配置则保持关闭。调度开启时每分钟核对一次，否则用“检查恢复结果”继续，每次手动核对至少间隔十秒。本实现只支持单进程运行。

恢复覆盖的是已经发现的缺正文记录，不发现未知历史文章，也不把图片、音视频转写或尚未入库的文章算作已恢复。本机真实文章当前均有正文，因此未对健康文章强制重取；完整恢复流程通过独立模拟上游、隔离资料库和真实浏览器验收，不宣称已验证真实缺正文的网络恢复成功率。

## 个人自测与复习（使用说明）

在公众号资料详情或考点页点击“加入复习”，把问答或提法加入 `/practice`。该入口也在全站收藏弹窗中。提法使用系统回想提示，不冒充原文试题，章节标题中自带的答案不会照搬进提示；原作者标星与答案待核对标记保留。

先回想，再展开原文答案和段落依据，记录“没想起、不熟悉、想起来了”。对应间隔为 10 分钟、1 天，以及连续回想后的 1/3/7/14/30 天（30 天封顶）；这是简单的个人安排规则，不代表客观掌握评估。默认显示到期卡片，可切换全部查看未来安排；支持撤销最近一次回想及移出复习，保留回想操作历史。

个人记录保存在当前浏览器当前站点的 IndexedDB，不写入共享资料库，不要求管理员口令，也不自动把收藏或已读当成掌握。浏览器正常关闭、重启或页面刷新后保留；清除网站数据、换浏览器或切换主机/端口后无法直接读取原记录，可使用下述 JSON 备份恢复。没有自动跨设备同步或账号体系；SQLite 数据库备份不包含这些浏览器记录。

每张卡绑定资料 ID、修订、条目类型及索引，保存当时的内容和原文依据。资料更正后旧卡不会被替换，会提示查看最新资料；新版需单独加入，复习进度从零开始。重复加入同一版本不重复建卡或清空进度。回想结果、下次时间及历史在同一 IndexedDB 事务保存，失败整体回滚；过期页面的并发操作被拒绝，避免覆盖新结果。

只读接口：`GET /api/practice/card/{material_id}/{revision}/{kind}/{index}`（kind 为 questions/points）以及 `GET /api/practice/versions`。缺少原文依据的条目不生成复习卡。浏览器调度规则测试：`node --test tests/practice_core.test.cjs`。

### 复习记录导出与合并恢复

在 `/practice` 的“保留自己的复习记录”导出 JSON，保存卡片的固定版本原文快照、复习安排及历史。数据只在浏览器本机处理，不上传；不包含收藏、已读、管理口令或 WeRSS 登录。备份上限 25 MB、5000 张卡片和 50000 条历史。导出在同一只读事务取得卡片与历史，不保存运行时并发令牌及撤销引用。

选择文件后先校验并展示数量，点击“确认合并恢复”才写入。本机已有同编号卡片及进度优先保留，缺少的卡片才补入；历史按事件身份去重。同编号内容不同时报告冲突并保留本机内容，不自动用备份覆盖。导入在同一事务写入卡片与历史，失败整体回滚。恢复的卡片重新生成并发令牌，不重建跨备份撤销关系。

换资料库可能出现同编号对应不同文章，因此恢复卡明确标为备份快照，提醒核对标题、作者及依据，不仅凭本机版本号认定原文一致。恢复不会导入整份新闻或公众号数据库；旧卡快照可回想，本机原文可能尚未存在。测试包括格式/版本拒绝、原文引用身份校验、重复恢复、冲突保留、写入回滚和浏览器重启后保留。

## 统一检索

全站顶栏“检索”进入 `/search`，从一处检索新闻标题/摘要/正文/来源/日期、公众号当前正文和作者，以及考点名称/科目。默认全部年份，新闻年份和来源条件仅约束新闻；空格分隔的关键词按全部命中处理，`%` 和 `_` 为普通字符。结果使用原文附近的摘录，按类型展示，不生成新的 AI 答案，也不把同词命中视为考点关联已确认。

全部范围每类先展示 5 条，进入单类后每页 20 条，排序稳定。只搜索当前库内资料，不搜索旧修订、浏览器复习数据、尚未采集的文章或图片/音视频正文。当前为 SQLite 直接查询，数据量扩大后再测性能与考虑统一全文索引，不宣称适用于无限规模。

`GET /api/search?q=关键词&kind=all|news|materials|knowledge&page=1` 提供分组计数及每类最多 20 条结果；可选 `year` 和 `source` 过滤新闻。关键词最多 120 字符。此次不增加业务表或改变数据库版本。

## 首页日期与自动显示更新

首页“今天，从这里接着学”串起三个入口：每位老师一份最近整理且具有原文依据的自测/提法材料；一个具有多个账号当前材料的考点；当前浏览器到期的复习卡。选材时间为入库整理时间，不冒充公众号发布时间。旧修订与已排除关系不进入多来源推荐；没有符合条件的资料时保留准备资料或原文阅读入口。

从材料开始回想、核对原文，再点击“加入复习”；回到首页即可查看到期安排。另一个标签页加入、记录回想或撤销时首页会同步读取本地记录，页面重新聚焦和每分钟也会检查。个人安排只在当前浏览器读取，不发送服务器；收藏、已读不会自动变成复习卡或已掌握。浏览器不能读取记录时显示明确提示，已有文章仍可读。

首页大日历显示系统当前时刻对应的北京时间，与“资料日期”分别标示。跨午夜、恢复可见、窗口重新聚焦或恢复网络时自动检查；可见状态每分钟读取一次 `/api/study/live`。后台标签页暂停轮询，返回即补查；请求失败保留当前资料并提示稍后重试，不将旧内容标成今天新稿。

页面只在版本变化时更新阅读区域，保留筛选、已读/收藏、仍存在条目的展开状态及位置；搜索输入期间暂缓替换，结束输入后接续。过时的跨日响应不能覆盖新日期。此接口只读库内已采集内容，不触发采集；新闻获取仍按已有定时任务运行，不能承诺每分钟都有外部新稿。没有今天的资料时明确显示最近资料的实际日期。

字号调整沿用纸页阅读风格：知识正文桌面 20px/手机 18px，来源标题 18px/16px，“加入复习”12px，正文中的段落序号与轻量按钮分层；重复原文证据按需展开。首页新闻标题 21px/19px，导读 17px/16px。测试模拟时钟与测试新闻仅用于独立验收环境，正式页面不注入模拟日期。

## Windows 本地应用（构建说明）

**当前暂停分发。** 已生成的压缩包仅是启动验证样品，不能视为朋友可直接使用的成品。先完成首次获取、采集错误恢复、内容审核及学习复习闭环，再按验收结果重新打包。下述保留为未来构建说明。

提供 PyInstaller 文件夹模式的本地启动器。构建机安装 `requirements-desktop.txt` 后执行：

```powershell
.\scripts\build_desktop.ps1 -Python python
```

生成 `dist/StudyRoom-Windows-x64.zip`。朋友解压整个目录后双击 `StudyRoom.exe`，无需安装 Python；程序自动打开浏览器，并提供更新近期新闻、配置 WeRSS 文章数据库、手动导入和打开数据目录的操作。首次运行不包含开发者的资料库、配置或登录信息；点击更新新闻后开始获取自己的内容。

运行数据独立存于 `%LOCALAPPDATA%/PoliticalNewsStudy`，升级程序目录不覆盖数据。数据库升级前自动备份；启动器持有系统文件锁，防止同一数据目录运行多个实例。本地网页固定使用 `127.0.0.1:18764`，保持同一浏览器的收藏与已读记录；关闭启动器会停止服务。端口已被占用时启动失败，日志可用于排查。

公众号自动采集仍需要使用者本机另外安装 Docker Desktop、部署 WeRSS 并扫码授权。选好其 `db.db` 后重启应用，启用每 15 分钟的导入；这里不包含 Docker 或 WeRSS 本身。没有配置 WeRSS 时仍能阅读和采集新闻。当前不含安装向导、代码签名和自动升级。

完整说明见 [本地版使用说明](docs/DESKTOP_GUIDE.txt)。打包资源按 [PyInstaller 官方用法](https://pyinstaller.org/en/stable/usage.html) 显式收集页面、样式、分词词典及时间区数据，未将项目目录整体打入分发包。
