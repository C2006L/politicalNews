# WeRSS 近90天历史采集适配器

此补丁针对本机固定镜像 `ghcr.io/rachelos/we-mp-rss@sha256:af771f21b3f7958a5dea16911fba050a6d7b92eac2fb2499c467c1b11f07ef34`。不替换微信读书基类、不引入额外依赖、不修改 WeRSS 表结构；保持现有账号 ID、订阅、数据库和登录文件。

## 修复范围

原部署的 `weread_mp.py` 仅调用 `/api/mp/cover`，每次最多得到最新一篇。当前授权失效时，`/web/mp/articles` 与书架都返回 `-2012`，但 cover 仍返回文章，导致“最新稿可用”掩盖历史缺口。重新扫码后，三个重点来源的历史首页实测均可访问。因此不能把一次业务错误视为接口永久失效。

补丁以历史列表为主：

- 初始历史扫描不会因为最新一篇已经入库就结束，而是继续到本期90天日期边界或接口空页。
- 中断进度存在 `/app/data/political-news-history.sqlite3`。每批先查最新页，再与历史断点的末组重叠继续；锚点不再出现时回到起点复核，不跨越未知缺口。
- `MaxPage` 是历史页数预算，上限6；续跑可能额外读取一页最新列表。默认1页能逐批推进历史，不必先调大环境变量。
- 实际入库且正文存在才跳过文章。正文失败、入库未确认不会推进该历史页；已保存的文章下次去重。明确的媒体/短文缺口单列，不阻塞同页后面的政策文章。
- 历史失败时可以保留最新稿兜底，但任务仍报告历史失败。登录受限、访问受限、部分完成和列表窗口扫描结束分别记录。
- `-2012` 本身不能区分授权失效和访问配额。统一标为原因待核实并退避30分钟，不能据此让用户反复扫码；用户实际更新授权文件后可再次验证。不会切换账号或出口规避限制。
- 长时间正文入库时由独立心跳续租；失效或被替换的租约不能复活，崩溃后仍可接管已保存断点。
- cover 没有刊载日期就保留未知，不再把抓取时间写成文章刊载时间。
- 正文保存为“原文正文与元数据快照”：完整保留正文容器、图片、链接、作者、标题及可安全解析的原始刊载元数据；不保留正文外的数MB站点脚本。脚本表达式不执行、不作为元数据复制。

“窗口扫描结束”只说明接口返回的列表已扫描，不代表已核实公众号官方90天总发布量。正文待补和学习材料另列，账户覆盖率仍不能凭此宣称100%。

## 安装、探测、执行

在主项目目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_werss_history_local.ps1
```

安装器校验固定镜像，先备份数据库和旧补丁，再替换本机 `werss-local/local-deploy/patches/weread_mp.py` 并重启 WeRSS。导入检查失败会恢复旧补丁。回滚文件位于工作区 `preview/history-adapter-日期时间/`，数据库备份位于 WeRSS 数据卷 `history-adapter-backups/`。不要把这些备份或授权文件提交 GitHub。

只读探测，不采集正文：

```powershell
Get-Content scripts/werss_history_doctor.py -Raw | docker exec -i -w /app political-news-werss /app/env_x86_64/bin/python3 - MP_WXS_2399587742 MP_WXS_3244729290 MP_WXS_3089222529
```

每号一页真实补采，沿用正常数据库回调，不执行消息推送任务：

```powershell
Get-Content scripts/werss_history_collect.py -Raw | docker exec -i -w /app political-news-werss /app/env_x86_64/bin/python3 - MP_WXS_2399587742 MP_WXS_3244729290 MP_WXS_3089222529
```

重复执行会续跑同一清单。授权在 WeRSS 的“微信读书管理→扫码授权”由用户本人完成，诊断和采集脚本不导出 Cookie。确认没有其他同号任务持有租约后再运行；不要删除进度文件强行重复启动。

主项目从只读快照导入：若 `content` 有可确认的原文正文容器，优先于 WeRSS 转换过的 `content_html`；原页和转换片段兼容。读取正文时逐条加载，避免一次缓冲200份大原页。覆盖页面只读显示适配器摘要，不展示文章 ID 明细、租约或凭据。

较大的已存原页导致原20秒快照导出预算不足，导出器现默认120秒、最高300秒；超时和替换失败仍保留旧快照，不能把导出失败当成“没有新文章”。已在本机实际完成一次约30秒的导出。

## 验收

离线测试验证：已存最新稿不阻断补旧、重启/锚点续跑、正文失败不跳页、写入确认、授权错误不伪装成功、元数据日期不造假、并发租约、媒体缺口、原文快照内容等价、只读状态及页面提示。还必须做真实列表、正文、入库、主项目导入和重复执行验证，不能以mock通过代替真实收录。

Redis保持现有关闭配置。新增进度库使用标准SQLite，不依赖Redis。Cloudflare按用户要求保持关闭，文章范围与正文验收尚未完成时不对外开放。
