# 本机续采与方向精选（2026-11-18）

## 本轮完成的范围

优先完成“通道恢复后继续采集”和“考研、公考分别精选”。既有资料库继续保留原文和历史版本；教材带背、备考建议不因来源权威或命中热词进入时政精选。Cloudflare 按用户要求保持关闭。

### 自动续采

- 本地启动脚本默认设置 `LOCAL_WERSS_HISTORY_WORKER_ENABLED=1`。每5分钟轮询一次，每次仅一个已启用、已绑定的公众号，调用固定容器 `political-news-werss` 内固定采集程序；不开放公网采集按钮，也不向主应用复制微信凭据。其他部署默认不启用此本机 Docker 任务。显式设为 `0` 可关闭。
- 沿用适配器分页断点、重叠页与文章入库确认。每批 `MaxPage=1`；恢复历史游标时会额外请求最新页及重叠页，必要时再前进一页，不将“1”包装成严格只发一次 HTTP 请求。正文请求按上游配置间隔进行。
- 未完成来源最短间隔5分钟；已扫描窗口的来源最短1小时增量检查。已尝试来源轮换到后面，避免一个失败账号占满队列。
- `-2012` 只表示授权或配额原因待核实，退避至少30分钟；不要求用户反复扫码，不因为最新一篇可读就宣告历史列表可用。退避到期后自动试下一批，成功时沿原断点继续。
- 微信验证码使该号进入 `verification_required`，不自动重复验证请求。人工完成验证后，维护者通过容器环境变量 `POLITICAL_HISTORY_VERIFICATION_CONFIRMED=<该号MP_WXS数字ID>` 显式执行一批原有采集脚本，确认可采后恢复定时轮换。其他账号继续独立处理。浏览器能打开文章不等于历史列表通道已恢复。
- 主应用保存任务回执；适配器保存运行编号、起止时间、最近列表成功、最近正文入库和最近成功批次。已保存但缺少旧成功时间的历史记录保持“尚无可核查记录”，不拿最近尝试补填成功时间。
- Docker 调度超时或完成结果不明时，停止派发新任务，等待同一运行编号的持久化完成记录。独立的 operator 回执覆盖账号退订、缺授权等进入适配器前的可确认失败。这些失败允许后续来源继续，但不算采集成功。
- 源级租约与心跳阻止重复入库；主应用 SQLite 事务和任务回执阻止多个应用进程重复调度。任务结果不明且没有回执时，维护者需先确认容器进程和对应断点，不能盲目清空状态或重跑。

状态入口：`/material-coverage` 与 `/api/material-coverage`。列表和正文的成功时间分别展示；待补数量、重试时间、运行中状态不会被合并成“已完成”。总量未知继续显示未知，不计算虚假的全号覆盖率。原有快照服务每60秒导出，主应用每15分钟导入；正文写入上游后不保证立即出现在阅读端。

正常启动仍使用 `scripts/run_learning_local.ps1`，保持电脑、Docker 和阅读服务运行。定时器随本地服务运行，电脑休眠期间不会持续抓取。无需为这个续采器额外启用 Redis。

### 方向筛选

- 首页精选所选方向实际执行相关性检查，全部内容仍可查。公众号时政补充与该方向一致；资料目录的“共同可读”范围不等于每日重点。
- 考研重点：全国重大会议与文件、明确重要讲话/指示/批示、周年纪念、理论框架、具有肯定成果信息的科技突破。仅出现 AI、交流会议或“尚未取得突破”不算科技成果。各省地方政策采用同一规则，不偏向山东。
- 公考重点：政策制度、三农基层治理、民生公共服务、产业绿色转型及具有具体问题/措施的官方评论。允许从评论开头识别正文议题，附原文片段作依据；不凭账号名称整号入选。
- 含蓄标题的署名评论须同时具备明确署名、公共议题与分析判断。仅在文学文章里提到“中国式现代化”，或者“政治理想”字符串里碰巧含“治理”，不作为治理话题。
- 政策文件优先于评论，评论优先于一般报道。评论仍以作者观点阅读；不把解释、案例或模拟答题材料改写成政策事实。
- 首页每日精选上限及同主题限额继续生效，不用无关文章凑数；空日期不会从别的日期借新闻。简报规则升级为 `period-extractive-4`，旧保存版本保持原样。

## 验证与边界

本机部署验证：适配器为 `history-90-v2`，部署文件与版本库副本 SHA256 一致。手动一个小批次和随后定时轮换的一个批次均取得持久完成回执，覆盖页及三个方向首页返回200。山东发布、腿姐的历史接口本次均返回 `-2012`，保存退避并保持未完成状态，没有把任务结束当作历史正文收录成功。此结果证明调度和失败回执闭环，不证明微信历史通道已经恢复。

本地另对26篇不同标题的真实已收录文章进行开发复核，检查6个考研正例、11个公考正例及各自反例，并与提交 `6538f63` 比较。样本包含重要指示、全国会议评论、农村治污、高校AI使用，以及食物健康、风景、商业活动、文学写作、带答案练习等反例。逐条原文依据和内容指纹仅保存于仓库外的 `preview/selection-review-20261118/report.json`，不提交原页或认证数据。这是针对已知问题的回归样本，不是独立准确率评测，也不证明报道事实已经核实。

尚未完成：公众号近90天完整发布分母、受平台访问限制的历史正文、全库误选漏选的独立人工评测、同学真实使用反馈及导航识别度测量。通道恢复后的完整窗口扫描仍取决于微信实际返回的列表与正文，不能仅凭程序修复宣告已补齐。

## 会话排查续做

`scripts/werss_session_probe.py` 可通过 Docker stdin 在 WeRSS 内运行。仅输出保存/生效会话是否一致、配置覆盖、重复Cookie名称、基础请求头是否齐全及书架/一个历史列表的响应码，不输出凭据，不续期或切换账号。明确区分“登录会话有效”和“公众号列表可读”。

本次旧授权保存位置正确，无旧配置覆盖或重复Cookie；书架与列表均返回带登录提示的-2012，正常续期返回-2013且未下发新Cookie。用户重新扫码后，授权文件更新时间变化、书架响应具有正常数据结构；列表曾返回有效20条记录，随后返回-2041。小批次采集未取得成功正文入库记录，不列作覆盖扩充完成。

程序修正：新授权文件与上次失败时不同时，调度器允许及时检查一次，沿用源级租约，不突破验证码暂停与运行中保护；失败后按新授权重新退避。适配器固定为与已部署扫码驱动一致的客户端标识，修正基类每次初始化随机切换桌面/移动UA的行为。该一致性修正不等于已经证明-2041由UA导致；固定后实测仍有该错误。删除了“只靠Cookie即可读取列表”的不可靠注释，保留已合法配置的网页列表ticket。

本机容器API前缀为 `/api/v1/wx`，管理登录路径是 `/api/v1/wx/auth/login`。扫码API `/api/v1/wx/weread/qr/code` 要求有效管理会话，与公众号采集用的微信读书会话分开；管理员JWT过期不能诊断为微信读书登录失效。管理页面缺少扫码入口时，本轮使用已有本机部署账号正常登录管理API后提供二维码，无需用户在聊天中提供Cookie。

验收：本轮全量479项通过，66个应用源文件类型检查和必要静态检查通过。新授权后对三个来源执行了有限批次，均因-2041暂停，未计为新增正文；固定UA后列表检查仍失败。另通过临时独立浏览器会话进入微信读书首页与书架，没有取得公众号列表请求或ticket，不将打开网页视为采集成功。当前仍待核验正常网页的公众号目录入口及其请求凭据；不应再次仅因-2041要求重复扫码。
