# 公众号历史补采修复与验收

日期：2026-11-18。近90天时政优先，学习合集单列；Cloudflare 暂停，未达到试用条件前不重新开放。

## 采集职责

WeRSS 当前 `weread_mp` 适配器用 `/api/mp/cover` 追踪最新一篇，它不能提供完整历史分页。现有部署明确关闭 Redis，并使用进程内队列及本地授权文件；开启 Redis 不会补出缺失的历史列表。保留 WeRSS 最新稿追踪，历史补采交给独立队列，不再依赖调大 `MAX_PAGE`。

历史入口分为全号历史主页、具体公开合集、正文关联链接。前者返回“请在微信客户端打开”时，只记录入口受限；不因此阻止仍可访问的合集或具体文章。合集完成不代表全号完成，官方网站补充稿也不计入公众号篇数。

## 已落地规则

1. 每个已绑定来源有独立的 SQLite `AppState` 清单，记录文章身份、发现途径、状态、尝试次数、时间、分类、失败原因；合集另存游标、已发现身份及声明数量。请求前后保存进度，重启不从第一页重新开始。
2. 从现有正文初始化；每次取得新正文，立即继续发现该正文内的历史文章与公开合集。短链接是待验证线索，只有页面账号名、账号 ID、mid/idx 均匹配才能合并身份。长短链接及重复目录项按账号 + mid + idx 去重。
3. 只解析静态元数据，兼容微信的空值回退写法，不执行页面脚本。跨账号长链接及站外链接不入该号清单；短链接取得后不属于该号即拒绝。
4. 近90天按原页刊载元数据计算，不拿采集时间充数。带背/备考建议另列；超窗、不属时政、日期不明均保留去向。不是仅凭公众号名称判断文章属于时政。
5. 每批总文章请求上限、每号目录页数上限、请求间隔明确；网络故障退避重试，三次后转人工检查。微信文字验证页和无提示的脚本验证页均停止该号，需用户手动验证后显式恢复。
6. 每号有带期限的独占租约；过期工作者不能覆盖新状态。已保存文章与清单进度分开提交，中断后重新核对已存身份，避免重复入库。
7. 正文质量与采集状态分开：保存了文字不一定完整可读。分页未齐、图片为主、正文缺失等不计为可读正文；保持原文版本，不伪造内容。
8. 覆盖页面与 API 优先读取实时清单，显示独立链接、可读正文、近90天时政待补、学习材料、超窗、未知日期及验证状态。各维度有交叉，不能相加。全号历史分母未知时覆盖率为 `null`。
9. 自动同步不再用文字片段替换已保存原页，即便上游标题、顺序或格式发生变化。变化片段只触发原页复查，核实原页后记录已接受的片段指纹，避免每次同步重复补采。原页未变化时不制造新版本，原有ID与引用保留。

## 本机执行

在项目目录中，用环境内 Python 执行，输出放仓库外。每个输出目录首次运行前自动备份主库；不会写入 WeRSS 上游库。

```powershell
cd D:\politicalNews\political-news
D:\politicalNews\.conda\python.exe scripts/backfill_public_albums.py --output D:/politicalNews/preview/history-check --discover-only
```

正常公开补采：`--source banyuetan --source people_comment --source dengta --max-articles 20 --max-pages 3`。多次运行继续同一数据库内的清单；输出目录只存缓存、备份和本批报告，不决定队列进度。

需要已授权的浏览器会话时，使用 Node 22+ 的本机桥接。专用 Chrome 需由用户本人完成微信验证，以 `--remote-debugging-port=9262 --user-data-dir=D:\politicalNews\preview\wechat-history-browser-profile` 启动。不要把调试端口对外开放。

```powershell
D:\nodejs\node.exe scripts/backfill_history_session.cjs --output D:/politicalNews/preview/history-run --source people_comment --max-articles 20 --max-pages 3
```

桥接仅在内存读取 `mp.weixin.qq.com` 的 Cookie，并通过子进程标准输入传递；不会写入参数、队列或报告。HTTP 跳转禁止离开微信域名。原页缓存含页面自身数据，留在本机，不随代码发布。

用户处理验证后追加 `--resume`；复查失败项后用 `--retry-failed`；重新检查已完成合集是否有新条目用 `--refresh-directories`。`--check-history-entry` 对该号历史主页做一次检查。学习材料单独用 `--scope learning`，默认不参与近90天时政批次。`--scope all` 是显式改变范围，不作为默认收录策略。

如果浏览器中能显示正文、同会话的 HTTP 请求仍被验证，继续保持采集暂停；单篇在浏览器可读不等于程序已恢复连续访问。当前未把未通过实际验收的浏览器批量抓取作为可用功能。

## 验收门槛

- 离线回归覆盖：递归发现、重启续跑、游标、长短链去重、错号/错篇拒绝、租约竞争、退避、显式恢复、日期窗口、未知日期、静默验证页、正文范围、全号分母未知。
- 某合集只有到达末页或达到可核实声明数量才能记目录结束。重复页/游标停滞单独报错；已到末页但数量少于声明，标为数量缺口。
- 每次真实补采报告区分新增正文、已有正文、待补、验证受限、学习材料和超窗。新增必须能打开保存的正文并回查原文身份；不把待采链接计作新增文章。
- 本地完整 flake8 必要错误检查、mypy 与 pytest 全通过；推送后核查 GitHub Actions。接口返回成功不代替正文可读性验收。
- 开放朋友试用前，逐号列出近90天时政的已知范围及缺口；对无法取得全号目录的来源明确提示，不宣称全量补齐。当前仍有平台验证和历史目录缺口，Cloudflare 保持关闭。
