## 用户重新明确的主线（2026-11-15，优先于下方历史阶段）

根本目标是整理时政，让用户知道发生了什么、哪些值得看、重复报道有什么新增信息，并能回查原文。公众号中的教材知识点仅为副产物，已有入口保留；暂停扩充知识点目录和复习体系。音频整理及教材核验不再作为当前产品的交付门槛，也不因此删去原文尚未审核的真实状态。

接下来按以下顺序推进主线：

1. **聚焦筛选（首轮已实施）**：区分时政事实/政策、时政解读、教材背诵、推广与一般备考建议；背诵、推广和一般备考建议不自动进入每日时政精选。给出入选理由，允许查看全部及纠正误分类；持续通过实际样本调整，不把规则当成事实核验。
2. **按事件整理（首轮已实施）**：保留同日同标题合并，新增不同标题报道的保守事件候选；对照原文、至少两篇当前稿确认后归并，可拆开并追踪维护记录。仅覆盖部分会议、具名政策与双边活动结构；通用语义归并、持续事件与后续进展仍待完成。
3. **重点与新增信息（本地对照首轮已实施）**：逐句识别重复、补充和近似表述差异，保留数字与否定变化及进展线索；尚不能判断独立报道、真正首次新增或系统重要性，不按转载数量加分。
4. **有依据的时政整理（原文摘录首轮已实施）**：事件页展示时间安排、举措、范围、数字等原句要点及出处；候选试读与已确认稿分开。尚未生成影响评估或通用多文语义综合摘要，不启用付费模型。
5. **每日/每周回顾（首轮已实施）**：按日期/自然周生成原文整理稿，可显式保存不可变版本，显示后续变化；不自动定时存档，仍非通用语义周报或影响分析。
6. **持续更新与质量闭环**：沿用已做的采集、快照和恢复机制，继续逐源体检、正文/日期质量、缺口与失败恢复验证，保证精选有真实内容供给。

现有基础可复用：多来源新闻、两个公众号、自动入库与首页刷新、检索/归档、原文与来源、收藏备份、运行状态及恢复。上述主线能力尚未全部完成；模型、事件语义聚合、评分与周期资料不因知识点功能已实现而视作交付。

先完善功能，再打包。用户选择 Windows 本地应用只确定最终分发方向，不代表要求立即交付压缩包。已有包仅为启动样品，暂停分发和重新构建，不以“EXE 能启动、页面返回 200”代表产品可用。

后续依次完成并验收：首次获取和失败重试 → 公众号采集/导入状态与缺口处理 → 考点与新闻关系的网页审核 → 统一学习、自测及复习路径。模型整理需要另行确认服务与预算。验收应从独立空库开始，真实取得内容并完成一次学习与再次复习，经过断网重试、重启与备份恢复后，再做干净 Windows 机器上的打包验收。

目标是为考研、考公用户自动整理最新时政：稳定采集权威媒体和精选自媒体，把同一事件的多篇报道关联起来，按集中报道程度与备考相关性区分重要性，再生成带原文依据的摘要和备考解读。

实施主线：采集质量与持续入库 → 事件聚合 → 报道统计与评分 → 有来源的 AI 总结 → 每日与周期资料 → 多用户试用与上线。

### 产品目标与范围

首版暂按“自己与朋友使用、重点服务考研政治”规划；公考与申论保留已有入口，暂不同时扩大新功能。目标是让用户完成：看到今天值得学的内容 → 理解和核对 → 回想作答 → 收藏或加入复习 → 下次继续。

### 第二批：从“按文章看”转为“按考点学”

建议增量模型，不推倒已有新闻与学习资料：

- SourceArticle / ArticleVersion：来源文章及不可变修订版本；现有 News 与 LearningMaterial 保留兼容映射。
- KnowledgePoint：稳定编号、学科章节、考试年份/教材版本、名称及别名。
- Evidence：文章版本、段落 ID、原文片段、支撑哪一条结论及适用范围。
- StudyCard：问题、答案、知识点、证据与审核状态；作者重点标记与系统排序理由分字段。
- ReviewRecord：用户对一张卡的回想结果与下次复习时间，先使用浏览器本地记录，后续需要跨设备再扩展。

实施要求：

- [ ] 先选 10–20 个实际考点建立人工关系样本，作为规则与后续语义模型的共同评测集。
- [ ] 先用规范化术语、章节及人工确认建立关系；不只按关键词、相同标题或作者标星自动合并。
- [ ] 同一考点下列出两位老师的对应材料与差异；冲突留待确认，不拼成一个无来源答案。
- [ ] 权威新闻仅在能支持某考点的事实或政策原文时关联；无关新闻留在资料库。
- [ ] 统一检索返回新闻、学习资料和考点，并明确内容类型；筛选条件、分页与来源链接保留。
- [ ] 老的 `/news/{id}`、`/learning/{id}` 和本地收藏键继续有效；可增加跳转到考点入口。

验收：选一个确实有多来源支持的考点，展示“考点 → 对照材料 → 证据 → 自测”的闭环；不要为演示而把 D28 思法与 D26 经济内容强行关联。人工标注样本上的误关联与漏关联分别记录。

### 第三批：学习入口整合，而非再增加一个独立栏目

- [ ] 在现有首页内逐步加入“今天的新材料、可复习考点、待复习卡片”，控制首屏信息量。
- [ ] 每日清单按新增材料、人工确认重点与用户未学内容组织，给出入选理由；不承诺押题概率。
- [ ] 无新文章时显示真实状态与可复习内容，不伪造每日更新。

### 模型接入与质量门槛

- 只向模型提供所选考点的相关证据，按文章指纹、提示词版本、模型配置和输出版本缓存；不每次刷新网页重新总结。
- 输出结构包括核心事实/考点、背诵提纲、易混点、来源差异、未确定事项及逐条引用；回答不得超出已提供材料。
- 关键数字、日期、否定词、范围词和引用 ID 做程序检查，检查失败进入待审核；检查通过也不等于内容完全正确。
- 只有可信证据足够时才生成统一结论；模型不可用、超时或预算耗尽时保留原文、规则卡片和已审核版本。
- 基于人工样本比较是否更省时、是否遗漏重点、是否曲解原意；先确定质量基线，再选择具体模型，不用“接上 API”代替验收。

### 暂缓事项与需要确认的信息

暂缓：扩展更多公众号、全平台爬虫、大规模历史回填、完整题库、复杂账号体系、跨设备同步、分布式架构和大面积视觉重做。

1. 首版对应哪一届考试、哪一版教材，是否仅聚焦考研政治。
2. 哪个模型服务可用，每日费用上限和允许发送的材料范围；密钥只放本地配置。
3. 仅自己/朋友私用，还是准备公开；文章与衍生材料的可展示范围。

### 验收标准：先定义，再测量

功能硬标准：早鸟带背/考研报名提醒误入公考为0；筛选恢复链接有效；来源数量不是筛选数量；XSS与版本固定保持；明确身份不符/验证页入库为0。

分类导航识别测试：建议至少5位实际使用者，每人完成6个相同任务（进入公考政策、找到指定老师、切换用途、查看被筛掉的原文、清除筛选、返回历史版本）。基线与新版使用相同内容快照，任务顺序对调，记录首次正确定位、误点、完成耗时及失败原因。截图只能对比静态识别，不能与真实交互耗时混比。

“提升80%以上”作为待实测目标，公式为(新版首次正确定位率-基线)/基线。基线为0时不计算；基线高于55.6%时，该相对目标受100%上限限制，不能声称一定可达。同步报告绝对正确定位率≥90%、误点率相对下降≥80%、成功定位中位耗时≤8秒。没有用户实测前，状态必须是“未验证”，不能用自动化测试通过替代识别度结论。

收录目标：已取得完整目录且确认属于近90天时政的清单，链接发现率目标100%，可访问有效正文入库率目标≥95%，其余逐条给出原因；分母只用已掌握的清单。全号近90天总量未掌握的来源，覆盖率标为未知，不能宣布达标。已知学习合集另报目录覆盖与正文覆盖，不占用时政指标。字段缺失/发布日期未知不计入已验证的90天指标。

样本整理目标：每个来源抽样，优先检查政策、报道、评论及容易误入的带背/生活文章；所有已抽样数字、单位、否定和条件保留原文。对误选、漏选分别统计并保留更正依据，不能只报总文章数。
